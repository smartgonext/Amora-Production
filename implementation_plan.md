# ERP Dynamic Form Builder & MS Word-Style Template Designer
## Updated Implementation Plan

This document outlines the phased plan to implement the **Dynamic Form Builder** (Phase 1) and a **Microsoft Word-style Visual Template Designer** (Phase 2).

## Phase 1: Dynamic Form Builder & Inline Dropdown Creator

### 1.1 Objective
Implement a multi-tenant dynamic form builder for ERP entities (Products, Services, Rentals, AMC Contracts, and Customers). Introduce quick-add capabilities with inline `+` icons for dropdowns so users can define new options instantly.

### 1.2 Database Schema
We will create two core tables to manage the structure, and reuse the values table for data mapping:

```sql
-- Form Sections (groups fields together in tabs or cards)
CREATE TABLE custom_form_sections (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    tenant_id BIGINT NOT NULL,
    company_id BIGINT NULL,
    entity_type VARCHAR(50) NOT NULL, -- 'product', 'service', 'rental', 'amc', 'customer'
    section_name VARCHAR(100) NOT NULL,
    sort_order INT DEFAULT 0,
    is_collapsed BOOLEAN DEFAULT FALSE,
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (tenant_id) REFERENCES tenants(id)
);

-- Form Fields
CREATE TABLE custom_form_fields (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    tenant_id BIGINT NOT NULL,
    section_id BIGINT NOT NULL,
    field_name VARCHAR(100) NOT NULL,
    field_key VARCHAR(100) NOT NULL, -- Unique key for serialization (e.g., custom_warranty_date)
    field_type VARCHAR(50) NOT NULL, -- 'text', 'number', 'select', 'multiselect', 'date', 'checkbox'
    placeholder VARCHAR(255) NULL,
    help_text VARCHAR(255) NULL,
    options_json JSON NULL, -- Stores dropdown values: ["Option A", "Option B"]
    is_required BOOLEAN DEFAULT FALSE,
    is_active BOOLEAN DEFAULT TRUE,
    is_static BOOLEAN DEFAULT FALSE, -- Core system fields are locked; custom fields are editable
    width VARCHAR(10) DEFAULT '100%', -- '50%' or '100%' width in CSS grid
    sort_order INT DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (section_id) REFERENCES custom_form_sections(id) ON DELETE CASCADE
);
```

### 1.3 Inline Add Dropdown Option Creator (`+` Button UX)
Every dropdown component generated by the form builder (and core forms) will contain a small, stylish inline `+` button. 

```
+-------------------------------------------------+
| Select Warranty Period:                         |
| +---------------------------------+  +--------+ |
| | Select option...              v |  |   +    | | <-- Opens Add Option Modal
| +---------------------------------+  +--------+ |
+-------------------------------------------------+
```

* **Action Flow**:
  1. Cashier/Admin clicks the `+` button next to a select field.
  2. A clean micro-modal pops up: *"Add New Option to [Field Name]"*.
  3. User enters the new value and submits.
  4. An API call instantly appends this option to the field's `options_json` in the database.
  5. The parent form dropdown refreshes reactively without losing any entered text or state.

### 1.4 REST API Endpoints
* `GET /api/custom-fields/schema?entity_type=<type>`: Fetch schema list sorted by section.
* `POST /api/custom-fields/sections`: Create new collapsible section.
* `POST /api/custom-fields/fields`: Create new field with type, label, and options.
* `PUT /api/custom-fields/fields/<id>/options`: Quick-append new option directly to `options_json` (used by the inline `+` button).
* `POST /api/custom-fields/reorder`: Send a lists of section/field IDs with their new positions.

### 2.4 Coordinate Math: Percentages to ReportLab Points
Because users can drag images and blocks anywhere, we save coordinates as percentages (`x_pct`, `y_pct`, `w_pct`, `h_pct`) relative to the A4 canvas bounds (`595px` width, `842px` height).

When printing, ReportLab converts these percentages into points ($1\text{ mm} = 2.8346\text{ points}$; A4 page width is $595.27\text{ points}$, height is $841.89\text{ points}$):

$$\text{X}_{\text{points}} = \left(\frac{\text{x\_pct}}{100}\right) \times 595.27$$

$$\text{Y}_{\text{points}} = 841.89 - \left[\left(\frac{\text{y\_pct}}{100}\right) \times 841.89\right] - \text{Height}_{\text{points}}$$

*(The subtraction from 841.89 is necessary because ReportLab's canvas coordinate origin starts at the bottom-left).*

### 2.5 ReportLab Coordinate-based Rendering Pipeline
```python
def draw_designed_template(c, data, layout_blueprint):
    """
    Renders elements dynamically at coordinate coordinates
    """
    for item in layout_blueprint['elements']:
        x = (item['x_pct'] / 100) * 595.27
        # Adjust Y origin for bottom-left conversion
        y = 841.89 - ((item['y_pct'] / 100) * 841.89) - ((item['h_pct'] / 100) * 841.89)
        w = (item['w_pct'] / 100) * 595.27
        h = (item['h_pct'] / 100) * 841.89
        
        if item['type'] == 'image':
            image_path = get_image_path(item['image_id'])
            c.drawImage(image_path, x, y, width=w, height=h, mask='auto')
            
        elif item['type'] == 'text':
            c.setFont(item.get('font', 'Helvetica'), item.get('size', 10))
            c.setFillColor(colors.HexColor(item.get('color', '#000000')))
            
            # Map dynamic variables (e.g., {{invoice_number}})
            text_content = map_template_variables(item['text'], data)
            c.drawString(x, y + h - 10, text_content)
            
        elif item['type'] == 'table':
            # Renders items grid inside dynamic bounding box
            render_dynamic_table(c, data['items'], x, y, w, h, item['style'])
```
